# DataShip 1.0.0-rc.8

- Administrace → Logy: historie posledních akcí a srozumitelné chyby workeru.
- Odesílání: poslední výsledek jednotlivých úloh.
- Upozornění v Jídelně a značka GUI používají MailShip.
- Sjednocená tlačítka pro ukládání a vrácení přehledu.
- Typy služby pro kalendář automatického odesílání se načítají ze skutečných názvů v JídelnaSQL (`public.varnedny`) bez předpokladu, že se nazývají „Oběd“.
- U každého odesílání lze vybrat **typ stravy podle přehledu, všechny kalendáře nebo konkrétní jeden či více kalendářů**. Výběr kalendáře ovlivňuje pouze varné dny; obsah PDF zůstává podle uloženého přehledu.
- Výpočet následujícího varného dne používá pouze přesnou shodu vybraných typů, bez porovnávání začátku názvu. Chybějící nebo neplatný kalendář způsobí srozumitelnou chybu, nikoli odeslání podle jiného.
- Při všech typech se bere nejbližší den, kdy má alespoň jeden skutečný kalendář hodnotu `A`. Pokud je vybráno více kalendářů, berou se pouze jejich dny.
- Starší úlohy bez profilu si ponechávají dosavadní kalendář **bez tichého nahrazení**. Pokud obsahuje neexistující typ (např. `Oběd` při skutečných názvech `Oběd-A`, `Oběd-B`), je nutné v **Odesílání → Upravit → Kalendáře varných dnů** vybrat skutečné kalendáře a uložit. Dokud se neopraví, úloha neodešle podle náhodného kalendáře.
- Nová instalace nemá předvyplněný fiktivní kalendář `Oběd`.
- Oprava uzavírání databáze historie na Windows.

## Instalace a aktualizace

Pro Windows x64. Balíček s příponou NSSM obsahuje také správce služby.
Názvy DataShip.exe a DataShip-Worker.exe zůstávají kompatibilní.

Před aktualizací zastavte službu a GUI. Zálohujte provozní konfiguraci, daily_reports.json, web_mail_tasks.json, web_mail_settings.json, web_mail_worker_state.json, přístupové údaje a složku logy. Aktualizujte kompletní aplikaci včetně workeru; nepřepisujte provozní konfiguraci ukázkovou z balíčku. Po přesunu instalace opravte cesty zastavené služby.

Historie se zaznamenává od aktualizace workeru, staré textové logy se neimportují. Smazání stavu workeru může vést k opakovanému odeslání.

## Ověření a omezení

Vydání vzniká pouze po úspěchu Windows regresních testů, buildu obou EXE a izolovaného smoke testu GUI, workeru a NSSM. Smoke test neobsahuje odesílací úlohy. Skutečné e-maily při přípravě vydání nejsou odesílány. Počty zákaznické databáze a přístupy pod cílovým účtem služby je nutné ověřit v cílovém prostředí.
